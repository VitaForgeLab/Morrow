## 0. 毕业设计背景

**课题名称**：基于大语言模型的超声检查智能问答系统设计

**简介**：针对超声检查知识专业性强、检查流程及注意事项查询不便等问题，设计一套基于大语言模型的超声检查智能问答系统。系统以超声检查指南、检查流程、检查前准备及常见问题等资料为知识来源，实现专业知识检索、多轮问答、答案生成和参考来源展示，为用户提供便捷、规范的超声检查信息咨询服务。本系统主要用于健康科普和检查流程咨询，不替代医生诊断与治疗建议。

**课题要求**

1. 调研大语言模型、智能问答、语义检索及 RAG 相关技术。
2. 整理甲状腺、颈动脉、腹部等常见超声检查资料，构建专业知识库。
3. 实现文档处理、语义检索、答案生成和多轮对话等功能。
4. 开发 Web 交互界面，支持用户提问、历史记录和答案来源展示。
5. 设置医疗风险提示、敏感问题处理和个人信息保护机制。
6. 构建测试问题集，评价回答准确性、相关性、安全性和响应速度。
7. 完成系统源代码、测试报告、使用说明书及毕业论文。

**研究重点**

1. **超声知识库构建**：完成检查指南、操作流程、检查前准备及常见问题等资料的分类、清洗、分段和向量化存储。
2. **专业知识语义检索**：根据用户问题检索相关超声知识，提高专业术语和相近表达的匹配能力。
3. **检索增强答案生成**：引导大语言模型依据知识库内容回答，并展示答案的参考来源。
4. **多轮对话管理**：结合历史对话理解上下文，实现连续咨询和追问。
5. **系统安全与评价**：减少无依据回答，对诊断、用药及紧急症状等问题进行风险提示，并评价系统回答质量。

> 课题要求第 5 条（风险提示、敏感问题处理、个人信息保护）**从阶段一就要埋钩子**（见 [v1 §7.5](v1_prd.md)），本阶段加固。

## 1. 阶段目标

把 Morrow 从"能聊天的套壳"升级为"**有据可依、可溯源**的超声知识问答"：

> 用户提问 → 语义检索知识库 → 检索结果与问题一起交给模型 → 模型基于依据作答并标注引用 → 前端展示答案与来源。

完成标志：对超声检查相关问题，系统给出的答案能指向具体知识库片段，且对知识库外的问题明确说"未找到依据"而不是编造。

## 2. 检索链路（端到端）

```text
[离线：知识库构建]
原始资料（指南 / 流程 / 准备事项 / FAQ，PDF 或网页）
  → 文档解析（MinerU：PDF → Markdown）
  → 清洗（去页眉页脚、目录、参考文献；统一术语）
  → 分类与元数据标注（部位：甲状腺 / 颈动脉 / 腹部；类型：指南 / 流程 / 准备 / FAQ）
  → 切片（chunk）
  → embedding（向量化）
  → 存入向量库 + MySQL 元数据

[在线：检索增强生成]
用户问题
  → （可选）查询改写 / 术语归一
  → 混合检索：BM25 稀疏检索 ∥ 向量稠密检索
  → RRF 融合
  → Reranker 重排 → Top-K chunk
  → Prompt 组装（强制"仅依据给定资料回答"）
  → LLM 生成
  → 答案 + 引用来源 [1][2] → 落库 + 前端展示
```

### 各环节要点

| 环节 | 要点 | 状态 |
| --- | --- | --- |
| 解析 | MinerU 转 md；表格与图注的处理策略 | 工具已定 |
| 清洗 | 去噪 + 术语统一（同一检查项的不同叫法要归一） | 待做 |
| 切片 | 按语义段落而非固定长度切；`chunk_size` / `overlap` 需要实验确定 | 参数待定 |
| 元数据 | 每个 chunk 必须带来源文档、章节、页码 → 引用才可溯源 | 必须做 |
| embedding | 以中文医疗术语的检索效果为第一判据 | 模型待定（§3） |
| 向量库 | 部署成本 vs 检索能力 | 待定（§3） |
| 混合检索 | BM25 负责术语精确命中，向量负责语义相近表达 | BM25 实现待定 |
| 融合 | RRF（无需调权重，起步首选） | 已定 |
| 重排 | Reranker 提升 Top-K 精度，代价是额外延迟 | 模型待定 |
| 生成 | Prompt 强制引用依据；无依据时必须说"不知道" | 已定原则 |
| 引用 | 答案里标注 `[1][2]`，与前端 chunk 卡片一一对应，且**落库** | 必须做 |

## 3. 技术选型决策表（待定项）

> 这张表是给阶段二开头用的。**决策理由要写在这里**，不要只留在脑子里 —— 毕设课题要求 1（调研）需要这些素材，论文的"技术选型"章节也直接来自这里。

| 决策项 | 候选 | 判据 | 当前倾向 |
| --- | --- | --- | --- |
| 向量存储 | pgvector（迁移 PostgreSQL）/ Qdrant / Milvus / Chroma | 部署成本、能否与 BM25 一体化、本机性能 | **待评估**。Milvus 部署较重，本机可能吃不下 |
| 数据库 | 继续 MySQL + 独立向量库 / 迁移 PostgreSQL + pgvector | 迁移成本 vs 组件数量 | 阶段二**开头**决定，不要拖 |
| embedding | BGE-m3 / bge-large-zh / 商用 API 模型 | 中文医疗术语效果、是否需本地推理、向量维度 | BGE-m3 是资料与老师参考文献里的常见选择 |
| reranker | bge-reranker-v2-m3 / 商用 rerank API | 延迟增加 vs 准确率提升 | 待实验对比 |
| BM25 实现 | Elasticsearch / `rank_bm25` / PostgreSQL 全文索引 | 运维组件数量 | 优先轻量方案，避免为一个 BM25 引入 ES |
| 融合策略 | RRF / 加权求和 | 调参成本 | **RRF 起步**（无需调权重，效果稳定） |
| 生成模型 | 沿用阶段一的 OpenAI-compatible 配置 | 长上下文能力、成本、中文医疗表达 | 沿用阶段一，不引入第二套调用方式 |

## 4. 数据模型增量

在阶段一四张表基础上新增：

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `knowledge_base`（可选） | id, name, description, created_at | 多库隔离。**建议现在抽出**，便于阶段三挂载超声以外的知识域（见 v3 §4） |
| `document` | id, knowledge_base_id, title, source_type(指南/教材/网页), category(甲状腺/颈动脉/腹部), raw_path, file_hash, status, chunk_count, uploaded_by, created_at | `file_hash` 用于去重与增量更新 |
| `document_chunk` | id, document_id(FK), chunk_index, content, token_count, page_no, section_title, embedding_ref / vector, created_at | 元数据字段是引用的基础，不能省 |
| `citation` | id, message_id(FK → message), chunk_id(FK → document_chunk), rank, score, created_at | **必须落库**，不能只在前端拼 |

### 4.1 向量存储的两种走法

- **走 pgvector**：`document_chunk.embedding VECTOR(1024)`，向量与文本同库，可用 SQL 直接算相似度，组件最少。代价是迁移 PostgreSQL。
- **走 MySQL + 独立向量库**：MySQL 存 chunk 文本与元数据，向量库只存 `chunk_id → vector` 的映射，两边靠 id 对齐。代价是组件变多、要保证两边一致。

**无论哪种走法，`citation` 表都是"参考来源展示"与"引用准确率评估"的共同基础。**

## 5. 评估口径（毕设课题要求 6）

| 指标 | 定义 | 测量方法 |
| --- | --- | --- |
| 引用准确率 | 被引用的 chunk 是否真的支持该答案 | 人工标注抽样；可选 RAGAs 自动评估 |
| 幻觉率 | 答案中无知识库依据的断言占比 | 人工评分 1–5 + 抽样复核 |
| 回答相关性 | 是否回答了用户真正问的问题 | 人工评分 + 模型打分交叉验证 |
| 检索质量 | context recall / precision @K | 标注"问题 → 期望片段"对 |
| 安全性 | 诊断 / 用药 / 急症类问题是否按预期拒答并提示就医 | 专门的对抗性问题集 |
| 响应速度 | 首 token 延迟、总时长（P50 / P95） | 压测脚本记录，分段计时（检索耗时 vs 生成耗时） |

### 测试集构建

覆盖 **三个部位**（甲状腺 / 颈动脉 / 腹部）× **四类问题**（流程 / 准备事项 / 科普解释 / 应拒答），
每条问题标注"期望引用的文档片段"，用于算检索指标。

> 测试问题集本身就是毕设交付物之一（课题要求 6），要单独成文件、可复现。

## 6. 安全与合规（毕设要求 5，本阶段加固）

- **风险问题分类**：诊断类、用药类、急症症状类 → 拒答模板 + 引导就医（阶段一已有 prompt 层钩子，本阶段升级为规则 + 分类双保险）。
- **知识库外的问题**：明确回答"知识库中未找到依据"，不编造。
- **日志脱敏**：不记录用户完整提问原文，或做匿名化处理。
- **免责声明**：随每轮回答附带，而不只放在页面底部。
- **引用可核验**：用户能点开来源，这本身也是降低误导风险的手段。

- 答案下方展示**引用来源卡片**：文档名 + 章节 + 片段摘要 + 相似度分数，可点开定位。

## 8. 学习任务

**要学**：

- RAG 基本范式与"检索增强"到底增强了什么
- 向量检索与相似度度量（余弦 / 内积 / 欧氏）
- embedding 原理与选型依据（维度、领域适配、推理成本）
- BM25 稀疏检索的原理与适用场景
- RRF 融合为什么不需要调权重
- rerank 与检索的区别（粗排 vs 精排）
- 切片策略对检索效果的影响
- Prompt 引用约束的写法（如何让模型"没有依据就说不知道"）
- RAG 评估方法（含 RAGAs 等自动评估框架）

**不学**（本阶段不碰）：

- 微调 embedding 模型 / 训练 reranker
- 分布式向量库的运维与扩缩容
- Agent 框架（LangChain / LangGraph 等，属阶段三）
- 多模态检索与图像理解（课题是知识问答，不是影像诊断）

## 11. 与阶段三的衔接

本阶段需要为阶段三预留的两处设计（详见 [v3 PRD](v3_prd.md) §4）：

1. `knowledge_base` 表现在抽出，便于阶段三挂载超声以外的知识域。
2. `citation` 表让"这次回答基于哪些依据"可追溯 —— 阶段三的记忆系统需要同样的可追溯性。
